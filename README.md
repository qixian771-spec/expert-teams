# 专家团 · Expert Teams

一套**端到端的产品专家团 Skill 集合**，目标只有一个：把一个模糊想法，一路变成大众可用的产品。

覆盖从「需求了解 → 产品定义 → 设计 → 编码实现 → 研发协同 → 测试验收 → 上线 → 产品管理 → 内容/短视频生产」的完整链路。每个团队都是一个独立的 CodeBuddy Skill，可单独召唤，也可按生命周期自动编排交接。

> 本仓库所有团队均为 **MIT 许可**，可自由使用、修改、再分发。

---

## 一句话定位

| 团队 | 解决什么 | 核心能力 |
| --- | --- | --- |
| **产品专家团** | 想法→产品 全流程 | 6 专家端到端编排：调研/产品/设计/开发/测试/产品管理，内置 Deep Research 引擎 + RICE 优先级 + 需求-测试追溯 |
| **编码实现专家** | 「开头顺、后面烂」 | 专治跑错入口、脏区、假实现；固化 spec→入口登记→原子提交→假实现扫描→验证→清脏区→ship 闭环 |
| **开发专家** | 带研发、跟研发 | 技术方案评审、任务拆解、依赖图与并行波次、排期风险、阻塞识别 |
| **内容创意专家团** | 文案 + 短视频内容 | 爆款调研→多变体生成→评分→迭代 可跑闭环，内嵌文案/短视频方法论 + 评分引擎（低分打回） |
| **创意多媒体专家团** | 视觉/UI/短视频美术/音频 | 4 专家按「定调→分领域落地→合成交付」编排，含平台物料规格库与尺寸查询脚本 |

## 安装方式

CodeBuddy 的 Skill 加载目录是用户本机的 `~/.codebuddy/skills/`。把需要的团队整目录复制过去即可：

```bash
# 安装全部 5 个团队
for d in 产品专家团 编码实现专家 开发专家 内容创意专家团 创意多媒体专家团; do
  cp -r "$d" ~/.codebuddy/skills/
done

# 或只装某一个
cp -r 编码实现专家 ~/.codebuddy/skills/
```

安装后，在 CodeBuddy 对话里用对应关键词即可召唤（例如「想法变产品」「写代码/假实现」「技术方案/任务拆解」「文案/短视频」「视觉/UI 设计」）。

> 注意：团队内部引用统一使用 `~/.codebuddy/skills/<团队名>/...`，请确保整目录复制、不要改名，否则内部脚本与 agent 路由会找不到文件。


## 设计原则

- **深度端到端，不是模板堆**：每个团队都内嵌方法论、可执行工作流、评分/校验迭代闭环、真产物、失败模式兜底。
- **可执行的产物**：不只是文档，每个团队都带可跑的 Python 脚本（优先级排序、覆盖率检查、假实现扫描、依赖图、内容评分、平台规格查询）。
- **按需召唤 + 自动编排**：既能单独召唤某专家，也能由「产品专家团」按生命周期自动路由交接。
- **补工具补不了的位**：例如 GSD Core 不管的入口漂移、脏区、假实现，由编码实现专家专治。
