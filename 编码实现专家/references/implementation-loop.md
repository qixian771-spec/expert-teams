# 正确实现闭环 —— 从 spec 到干净 ship

> 取代"给任务表→跑→改→再跑"的野路子。每一步都有产出、卡下一关。
> 同时给出与 GSD Core 命令的对应关系（如果你在用 GSD Core）。

## 闭环总览

```
① spec 先行      产出 REQUIREMENTS.md(REQ-ID + 验收标准)   [GSD: /gsd-discuss-phase]
② 入口登记      产出/更新 ENTRY.md                        [规则: 新增入口先登记]
③ 任务拆解      产出 PLAN.md(原子任务 + 验收点)            [GSD: /gsd-plan-phase]
④ 实现+原子提交  每任务一次 commit                          [GSD: /gsd-execute-phase]
⑤ 假实现扫描    fake-impl-checklist 全过                  [verify 前置]
⑥ 结构化验证    自动测试 + 假实现扫描 + UAT                [GSD: /gsd-verify-work]
⑦ 清脏区/旧代码 死代码/重复/废弃清理                        [定期/每milestone]
⑧ ship          干净 PR                                    [GSD: /gsd-ship]
```

## 各步要点

### ① spec 先行
- 先把"要做的"写成带 REQ-ID、可验收的需求，再写代码。
- 灰区问死（discuss），不写清楚不动手。
- **没有 spec 不写代码**。

### ② 入口登记
- 维护 ENTRY.md（见 entry-registry.md）作为唯一真相源。
- 新增页面/接口/命令前必须先登记；跑之前对齐它。

### ③ 任务拆解
- 每计划 2–3 个原子任务，每个带明确验收点。
- 任务太大 → 拆小，别一口吃成胖子（AI 单次做不完会烂）。

### ④ 实现 + 原子提交
- 每完成一个任务就 `commit`（conventional commit）。
- 功能用独立分支；工作树不堆未提交改动（否则脏区）。

### ⑤ 假实现扫描
- verify 前跑 fake-impl-checklist.md：硬编码/TODO/没接线/假测试/假完成。
- 只有"真接线"才算 done。

### ⑥ 结构化验证（三层）
1. 自动测试跑通；
2. 假实现扫描清零；
3. UAT 按 REQ-ID 验收点逐条人工验证。
- 发现问题 → 定位根因 → 修复 → 复验（闭环），不是"改完直接再跑"。

### ⑦ 清脏区 / 旧代码
- 检测死代码 / 未引用 / 重复 / 废弃入口 → 重构或删除。
- 每 milestone 扫一次；小步重构，前后跑测试。

### ⑧ ship
- 预检（验证过、工作树干净、分支对、可推）→ 建干净 PR（过滤中间产物）。

## 反例（你现在的方式，别再这么干）
```
给任务表 → 跑 → 发现问题 → 让AI改 → 再跑 → （入口漂/脏区堆/假实现漏检）
```
缺了 spec、入口登记、原子提交、假实现扫描、定期清旧代码——所以"开头顺后面烂"。
