# PRD 标准结构模板

> 使用说明：本模板供「产品专家」撰写 PRD 时套用。每条功能需求须遵循 EARS 原则（见 ears-cheatsheet.md）。

## 1. 背景
- 业务背景 / 问题来源
- 现状与痛点（数据或用户反馈佐证）
- 为什么要做这件事

## 2. 目标
- 业务目标（可量化，如转化率 +X%、客诉 -Y%）
- 用户目标
- 成功标准 / 非目标（明确不做什么）

## 3. 用户故事
> 格式：作为 <角色>，我希望 <功能>，以便 <价值>

| 编号 | 角色 | 诉求 | 价值 | 优先级 |
|------|------|------|------|--------|
| US-1 | | | | |

## 4. 功能清单
| 功能模块 | 功能点 | 类型(新增/优化/下线) | 优先级 | 需求描述(EARS) | 备注 |
|---------|--------|---------------------|--------|---------------|------|
| | | | | | |

## 5. 流程说明
- 主流程（正常路径）
- 分支流程
- 时序图 / 流程图（可用 Mermaid）

## 6. 交互说明
- 页面 / 入口
- 关键交互步骤
- 状态（空态 / 加载态 / 错误态 / 权限态）
- 边界与异常（见第 7、8 点）

## 8. 验收标准
- 功能验收（逐条对照功能清单的 EARS 描述）
- 边界验收（极限值、空数据、弱网）
- 异常验收（失败、超时、并发）
- 权限验收（角色 / 数据权限）
- 兼容性验收（机型 / 浏览器 / 版本）
